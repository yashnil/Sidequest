# Public-launch hardening audit

Audited 2026-10-24 against `main` @ 3871b67. This was a read-only audit: no source files were changed. Paths are relative to `apps/web/` unless they start with `packages/` or `docs/`.

## What is already solid

- **Headers.** `next.config.ts:28-61` applies a CSP (`frame-ancestors 'none'`, `object-src 'none'`, `base-uri`/`form-action 'self'`), HSTS (1 year, includeSubDomains), `X-Frame-Options: DENY`, `nosniff` and `Referrer-Policy: strict-origin-when-cross-origin` to `/:path*`. It also sets `poweredByHeader: false`.
- **Authorization.** One boundary, `lib/net/trip-access.ts:73-99`, enforces account first and then the cookie. All 11 `trips/[id]/**/page.tsx` call `ownedTrip`. Every trip-scoped action calls `tripAccessRefusal`, `editContext` or `reconciledContext`. So do the API routes: progress, scan, place-photo, calendar and the card routes. `(product)/ownership.architecture.test.ts` checks this and passes (25/25).
- **Cookies.** The session cookie is httpOnly, SameSite=Lax and Secure in production (`lib/net/caller.ts:96-121`). The auth cookie matches (`lib/auth/session.ts:38`). Budget identities need a signed token (`caller.ts:236`).
- **CSRF on server actions.** No `serverActions.allowedOrigins` is set, so Next 16's default Origin-vs-Host check applies. Lax cookies keep cross-site POSTs from carrying the session.
- **XSS.** There is no `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML` in `src/` (vendored MapLibre aside). React 19 blocks `javascript:` hrefs.
- **Prompt injection.** Third-party text goes in a JSON-encoded `untrusted` turn under a cached system policy (`lib/providers/anthropic.ts:105-117`). That covers booking imports (`lib/execution/import-model.ts:73`, redacted, capped at 60 KB), refinement requests (`lib/refine/interpreter.ts:311`) and the interpreter (`lib/providers/interpretation-model.ts:229`).
- **Spend control.**
  - A daily model-call ceiling with per-caller rows (`lib/compiler/daily-ceiling.ts`).
  - Token-bucket fences on every billable action, plus a deployment-wide fence at 8x (`lib/net/rate-limit.ts:212-330`).
  - Nominatim is serialised at 1 request per second (`lib/providers/nominatim.ts:30,59-69`). Overpass is cached and backs off on 429 (`lib/providers/overpass.ts:537-610`).
- **Data deletion of a trip.** `deleteTripAction` deletes the trip, and the ~50 child tables cascade with `ON DELETE CASCADE` and `foreign_keys=ON` (`lib/db/client.ts:38`).
- **Labs is closed on Railway** unless `SIDEQUEST_LABS_TOKEN` is set (`lib/net/billable-surface.ts:120-128`), on pages (`proxy.ts`) and in actions.
- **Ops basics.** `/api/health` checks the database. `/api/readiness` caches its probes (`lib/readiness/probe-cache.ts:51`). The server refuses to start on bad required config (`instrumentation.ts`). A backup script uses SQLite's online backup API (`scripts/backup-db.mjs`).

## Mobile native app feasibility

There is no `apps/mobile`. `packages/core` is pure TypeScript plus zod with no Node built-ins (a grep over core, geo and planner found none; `pricing/model-rates.ts` only mentions `server-only` in a comment). It exports TS source (`main: ./src/index.ts`), so an Expo app could import schemas, scoring, calendar and the execution graph through Metro workspace resolution.

The real blocker is that the product logic and every write live behind **Next server actions** (`apps/web/src/lib/**`, SQLite, providers). Server actions are not a stable or versioned client API.

**Recommendation:**
1. Launch as a PWA. It is already installable, with offline trip pages.
2. If native is needed, wrap the PWA (Capacitor or TWA) for store presence first.
3. Build Expo later as a thin client over a new versioned JSON API (`/api/v1/trips/...`), with token auth reusing `auth_sessions`, while sharing `@sidequest/core` for types and rendering logic.

## Items needing owner/legal review (not engineering-decidable)

1. **Privacy Policy and Terms text:** lawful basis, retention periods, subprocessors, international transfer (Anthropic US), children's use, and whether diet and accessibility facts count as special-category data under GDPR Art. 9.
2. **Anthropic data use and retention terms** for traveller text and booking emails sent to the model. Decide whether to disclose this or get consent before an import.
3. **Google Maps Platform terms:** storing `place_id` refs on `package.anchors[].identity`, showing Places content off a Google map, and photo attribution. `.claude-private/BLOCKER-google-terms.md` already flags durations, polylines and names.
4. **Nominatim and Overpass usage-policy fit** for a public product, versus paying for a geocoder or POI provider.
5. **Wikimedia image licences:** the per-image CC BY-SA attribution and ShareAlike obligations on the generated share and OG cards (cropping is already treated as a licence decision in `DestinationImage.tsx:79-85`).
6. **A daily dollar budget** to replace the call-count ceiling: at Opus 5 rates ($5/$25 per million tokens, `anthropic.ts:156`), 800 calls is potentially hundreds of dollars a day. Also decide whether anonymous users may spend at all.
7. **Data retention policy:** anonymous trips are never swept, and the cookie lasts 180 days (`caller.ts:72`). Decide how long unclaimed trips, `auth_states` and `trip_feedback` are kept.
8. **Safety, visa and entry content disclaimers,** and liability wording for "Ready" or feasibility verdicts.
9. **Support SLA and the abuse/takedown contact** to publish.
10. **Cookie consent:** only strictly necessary cookies appear to be used. Confirm there is no analytics, then decide whether a banner is needed in the EU.
