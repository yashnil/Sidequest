# Evaluation v3 — deviations from PROTOCOL.md

1. **The new build's first pass found a release-blocking defect, so the new build was re-run in full on the fix.** At `a187b19` every new-build scan failed: the discovery wire schema (with the new pillars and trail-stage fields) compiled to a grammar the provider rejected ("The compiled grammar is too large"), the call fell back to prompt-only output, and the model returned malformed JSON (`invalid_model_response`, verified by a live probe field by field). Fixed in `f603b3b`; a follow-up (`2fe4efd`) stopped rural short hops being labelled metro/train. The failed rows are in `runs/discarded/`.
2. **A model-provider outage (2026-11-14 ≈01:40–02:40 UTC)** failed both builds' scans with `provider_unavailable` (the open-data fallback was also refused). The previous build's pass 1 (completed before it) is kept; its passes 2–3 were re-run afterwards. Nothing from the outage window is graded.
3. **Machine load.** Other projects' sessions on the same machine ran heavy jobs throughout (load averages 60–95 at times); Playwright timing is affected, provider behaviour is not. Any run that failed for a reason outside the app is re-run with the same run index and listed below.
4. **Two single-scenario failures, one per build, re-run alone with the same run index.** New run 1 `mountain-road-trip` (trip e899241d, 04:12Z) and previous run 2 `beach-island` (trip 01cca6c2, 04:46Z) both ended `discovery_failed · nothing_placed` — the geocoder refused or returned nothing for every candidate in that minute, the same signature on both builds, with the other six scenarios of each pass unaffected. The rows were re-run with `EVAL_RUN` unchanged (`runs/<build>/fill-<run>.log`); the failed rows are not in `scenarios.ndjson`.
5. **The graded "new" build (98ce484) regressed, so it was fixed and a third build was run.** The deterministic grades showed lower defining coverage on Tanzania (4.0→2.7 of 5), the point-to-point trek (3.3→2.0 of 6) and the Highlands (4.7→2.7 of 6), and Kyrgyzstan's longest day rising from 318 to 1,007 minutes. Root causes, each fixed in `04de949` with a regression test: (a) a car-free trip's foot matrix, now really measured and so trusted, lent walking times to bus and transfer legs printed as measured; (b) the "game drives" essential was met by three stops around one crater; (c) "Tour du Mont Blanc trek" was never read as a trail, so the trek was classed urban single base; (d) direct route checks never prioritised places no matrix cell reached. The fixed build ran three full passes as `runs/fixed/` on the same protocol, and **the blind comparison is previous vs fixed** — the build that ships. The 98ce484 rows are kept and graded as an intermediate result; no judge saw them.
6. **One post-hoc diagnostic, outside the frozen measures.** `slow_measured_rides` counts non-walk legs printed as measured at under 10 km/h (≥30 min). It was added after the results because defect (a) was invisible to the frozen measures; it is reported separately and is not part of `hard_n`. The frozen measures and the judges' rubric are unchanged.
7. **Fixes after the blind judging are not re-judged.** `2696db4` (a business never stands for a base) and `243d0b4` (no invented village trains, base-locality check, zone must fit longitude) answer defects the judges named. They were verified by unit tests and by targeted live runs (`runs/postfix/`: Kyrgyzstan ×2; `runs/final/`: Tanzania ×2, Kauai, Kumano, TMB), graded deterministically, and shown to no judge. The blind result in REPORT.md is previous vs `04de949`.
