# Sidequest — working rules

Sidequest scans a destination for candidates (one bounded model proposal, then providers), lets the traveller choose, plans the trip deterministically, then verifies, corrects, enriches and presents it. Product requirements live in `.claude-private/SIDEQUEST-PRODUCT-COMPLETION.md`; execution state in `.claude-private/SIDEQUEST-PRODUCT-CHECKLIST.md`; history in `.claude-private/PROGRESS.md`.

## Architecture rules

- **Planner-first (V1 Convergence, `.claude-private/V1-CONVERGENCE.md`, supersedes "the model draft is canonical").** The LLM is not the optimizer. Normal flow: composer → interview → **Discovery scan** (`lib/discovery-scan/run.ts`: one model call *proposes* candidates, bases and food areas; Places/Nominatim place them; the router or labelled estimates time them; `packages/core/src/scan/assemble.ts` writes a standard `CompiledRegion`, adopted on the trip) → Discovery Board → Build. With a board, `production-plan.ts#generateSidequestPlanForTrip` builds the structure with `planning/structure-planner.ts` (pure: priority = traveller status + fit + significance, greedy insertion by travel minutes, pace capacity, effort spacing, frequency, time-of-day slots, weather thresholds, tour ordering, lunch, backups, a reason for every drop) written as a `TripDraft` by `planner-composer.ts` — **no model call** — then the unchanged verification pipeline. Model composition is only the labelled fallback for a trip with no board (`package.planning.mode`), or `SIDEQUEST_PLANNING_MODE=model` for regression. Auto-pick is the same planner asked early (`planner-autopick.ts`); board picks equal plan picks. Never route a user CTA through `build.ts#buildItinerary`, and do not reintroduce `@sidequest/planner#planTrip` for day construction (it produced one-stop days and refused untimed transit — see the progress log).
- **The heavy compiler is optional, never a gate (Quality V1).** The old Overture compilation ("Explore experiences first") is a secondary path behind `SIDEQUEST_RESEARCH_PROVIDER`; the discovery scan above needs only the composition credential (or the fixture switches) plus a geocoder. Composition-fallback composition needs only `ANTHROPIC_API_KEY` (or the fixture composer) and verification uses `planning/verification-providers.ts` (geocoder + router, never the research model). Nothing on the normal path may consult `SIDEQUEST_RESEARCH_PROVIDER`, and no environment-variable copy may reach a traveller.
- **The composition call reads one TravelerBrief.** `packages/core/src/interview/brief.ts#buildTravelerBrief` renders the profile, trip facts, bookings and board signals as sectioned XML with hard rules first and Sidequest's assumptions marked `[assumed]`; `composition.ts` holds the stable system prompt (role, quality contract, five behavioural examples, output contract). Every impact-bearing interview field must change the brief or be listed in `brief.test.ts` as not for composition.
- **Every build carries its own audit.** `planning/preservation.ts` (every draft anchor's fate; silent loss must be 0) and `planning/quality-audit.ts` (deterministic structural checks, never a taste oracle, never deletes) run on every generation and persist on `itinerary.package`. Generation budget: 120 s product, model deadline 100 s, verification gets the remainder and returns DEGRADED COMPLETE rather than waiting.
- **Evidence verifies; it is never a world allow-list.** The composition call (`composition.ts`) receives traveller and trip context only — never the POI catalog, coordinates, hours, provenance or matrices. The reconciler (`reconcile.ts`) resolves only what the draft references.
- **Unknown ≠ false.** Missing geocoder, routing, hours or weather evidence lowers confidence (`partially_verified`/`unverified`, `unmeasured` legs) and never removes content. Only affirmative evidence corrects, with the smallest change.
- **No silent model-anchor loss.** Every draft anchor ends in exactly one `AnchorDispositionCode` on `itinerary.package.anchors`, and every non-scheduled one is explained on `itinerary.unscheduled`.
- **Bounded model calls.** One proposal call per discovery scan; zero for a planner build; one for the board-less composition fallback. No automatic retries, no repair model, no evaluator model. `skeleton-repair*.ts` stay unwired.
- **Live World V1 (`.claude-private/SIDEQUEST-LIVE-WORLD-V1.md`).** One capability registry (`apps/web/src/lib/providers/capabilities.mjs`, import-free, shared with `npm run doctor`) says what is real, fixture or off. Place resolution order: persisted identity → board → compiled → places provider → geocoder → unresolved; provider refs persist on `package.anchors[].identity`. Valhalla is the routing backbone; Google Routes/traffic/transit are explicit opt-ins (`SIDEQUEST_ROUTES_PROVIDER=google`, `SIDEQUEST_TRAFFIC_PROVIDER=google`, `SIDEQUEST_TRANSIT_PROVIDER=google`) because `.claude-private/BLOCKER-google-terms.md` forbids persisting Google durations, polylines and business names — Google display names are matched, never stored. Every measured leg carries `basis` (static / traffic_aware / scheduled / estimated), `provider`, `measuredAt` and, when a direct route answered, an encoded `geometry`; nothing static is ever called live. Booked facts enter the composition task before the one model call and are verified deterministically after. Day edits (move, reorder, duration, custom stop, must-keep) and "Fix this day" are local and never re-measure a leg silently (`not_remeasured_after_edit`). Discovery (stays, food) is a traveller-pressed server action for display only; live room prices and availability are never shown. Renders never call a provider.
- **Unknown travel time is never zero (Product Recovery V1, `.claude-private/SIDEQUEST-PRODUCTION-UI-V1.md`).** Every leg is in one `TravelDurationState` (`packages/core/src/travel/estimate.ts`): measured, scheduled, model_estimate, geo_estimate (Sidequest's own mode-aware figure from resolved coordinates, `provenance: estimated`, never a road km, never a hard-constraint trigger) or unknown (an allowance on the item, the day shown in day parts). A "walk" over 3 km is corrected by geometry. Routing hierarchy: local Valhalla inside its declared coverage (`SIDEQUEST_ROUTES_COVERAGE`) → openrouteservice (`routing.global`, direct legs only, api.heigit.org) → estimate. Bases are places to sleep (`baseKind`, the draft's locality as the display name, never a landmark the geocoder matched); anchors carry an `anchorKind` and only a `named_place` is ever "not verified"; a meal written as an activity is `folded_into_meal`; backups carry `dayNumbers`. The quality audit's temporal checks run regardless of providers.
- **Travel intelligence is deterministic and provider-free.** `apps/web/src/lib/intelligence/build.ts#buildTravelIntelligence` is a pure function of the persisted itinerary, draft, profile, booked items and readiness profile; it never calls a model or a provider. Booked facts (`booked-reconcile.ts#applyBookedFacts`) are applied over the pristine itinerary at load time and are never moved by the planner. Rules: unknown ≠ false, missing ≠ contradicted, stale ≠ current, model knowledge ≠ current legal fact, provider failure ≠ physical impossibility. Only `official_current` sources may confirm entry/visa/health/advisory claims (`packages/core/src/intelligence/claims.ts#CONFIRMING_AUTHORITY`). Static road routing is never labelled live traffic; a flight, ferry or guide transfer the router cannot route is plausible, never impossible. Spec: `.claude-private/SIDEQUEST-TRAVEL-INTELLIGENCE-V1.md`.

- **Traveler Intelligence OS (V6, `.claude-private/V6-TRAVELER-INTELLIGENCE.md`).** One `TripContract` (`packages/core/src/contract/trip-contract.ts`, assembled by `planning/trip-contract.ts` before the one call) holds every meaningful input with a lock: `booked_lock > hard_lock > user_explicit > user_soft > sidequest_inferred > model_proposed`. The model may never override anything at `user_explicit` or above; `enforceContractOnDraft` drops a contradicting field and records a `ContractConflict` on `itinerary.package.contract`. The timing lock is durable on the trip row (`trips.timing_lock`: `traveler` | `sidequest` | NULL) and every door that closes the question writes it with the dates; a locked row is never overwritten by a model window. People, not counts: `travelers` / `trip_party_members` (`packages/core/src/party/traveler.ts`), per-person diet and functional needs (planning consequences, never diagnoses), rendered as `<party>` in the brief; a member's hard rule is the group's hard rule; a strenuous day a member cannot do needs a `split`. Transport is not a POI: `anchorKindOf` folds transfers into legs (`folded_into_transfer`) and gateways into the terminal plan (`folded_into_terminal`); an "X or Y Airport" is `gateway_unresolved`. `FeasibilityReport` (`packages/core/src/feasibility/report.ts`) decides "Ready": feasible / feasible_with_cautions / unresolved_major_dependency / infeasible; an unmeasured base-to-base transfer is a dependency and the day says "major transfer not measured", never a small total. Accounts: `users` + `auth_sessions`; ownership is `trips.user_id` when set and the browser cookie only while unclaimed (`lib/net/trip-access.ts`); the guest claim moves only the presenting cookie's rows; `SIDEQUEST_AUTH_PROVIDER=fixture` is refused in production without `SIDEQUEST_AUTH_FIXTURE=allow`. Preference evidence (`preference_evidence`) learns taste only, never a constraint; refinements record trip-scoped leanings. A material refinement (≥3 days, a base, the route, the dates) is proposed before it is applied (`confirmMaterialChanges`), and Apply/Cancel cost no model call. Structural metrics (`quality/metrics.ts`) persist on `package.metrics` and are never collapsed into one score.

- **Destination semantics (V8.1, `.claude-private/V8.1-DESTINATION-SEMANTICS.md`).** A provider row is evidence, never truth: every part of the intent graph is resolved through the semantic gate (`packages/core/src/destinations/semantics.ts` — type, scale, name relation, country; `apps/web/src/lib/destinations/intent-resolution.ts`), so a business, road or neighbourhood never stands for a region, a same-named town stands for one only weakly, and the wrong country never stands for anything. Both doors (`trips/new/place-actions.ts`, `plan/actions.ts`) go through it. When the deterministic sources cannot settle a region-like part, the interpreter (`lib/destinations/interpretation.ts`, `SIDEQUEST_DESTINATION_INTERPRETER`, one bounded call, cached thirty days) classifies the concept and names areas and gateways; every name is geocoded and gated; the model never produces a coordinate. `DestinationIntent.semantics` carries type, scale, countries, an evidence-qualified centre and extent (`extent.source`: published / union_of_parts / interpreted_parts / none), parts and gateways (context, never the destination). The canvas frames by scale, never a 40 km box around a point; BEST_TIME samples up to three points across a regional extent and says so; the interview reads `signals.semantic` (a mountain region gets `mountain`, `weather_exposed`, `road_trip_region`; a desert `wilderness`). Regression corpus: `apps/web/src/lib/destinations/semantics-corpus.test.ts` on recorded geocoder rows (`fixtures/nominatim/`) and the recorded interpreter (`fixtures/interpretations.json`); `e2e/destination-semantics.spec.ts`. Never patch a destination by name.

- **World Model & Trip Intelligence (V7, `.claude-private/V7-WORLD-MODEL.md`).** What somebody typed is an intent to resolve, never a string to match: `parseDestinationIntent` (`packages/core/src/destinations/intent-graph.ts`) splits a phrase into parts, and `lib/destinations/intent-resolution.ts` resolves each part and unions the envelope; an unresolved part is never "not a place" (only the research path's explicit `not_a_place` reaches that screen). `municipality` is an entity type ("A city and its region") and is urban. How a country works is data: `packages/core/src/reality/jurisdictions.ts` keyed by ISO code, every fact with authority and `asOf`; `buildTravelReality` gives each mode concept a status independent of what a router can measure; **never write `if destination === '<place>'`**. The interview's transport options and default come from the reality; the split question needs a recorded party difference; a free-text note is read by the deterministic phrase table into chips (`noteReadings`) and stored verbatim. BEST_TIME defers the window to the review (`ReviewTimingCard`, `questionnaire/timing-actions.ts`), scored with interests and compiled crowd periods, accepted with the row lock. The wire carries `episodes`, a day `move` and `food`; a cruise, trek, safari or sleeper is one episode — vessel bases are not geocoded, in-episode legs are boat or trail legs on the operator's timing, never road legs (`planning/topology.ts` audits this; a missing episode entry/exit is a feasibility dependency). Generation progress writes real counters (`generation_progress.detail_json`), never a percentage. Map lines are drawn by mode (boat, rail, flight, trail).

- **Trip Execution & Decision Intelligence (V9, `.claude-private/V9-TRIP-EXECUTION.md`).** The Trip State Graph (`packages/core/src/execution/state-graph.ts`) is derived on every load from the applied itinerary, the intelligence snapshot, the booked facts and the traveller's recorded acts; it is never stored, and every V9 surface (Next Best Action, Preflight, Today, the calendar, the Pack, the ledger, the freshness banner, the dashboard card) reads it — no second source of truth. The only persisted execution rows are the traveller's acts and Sidequest's observations (`trip_decisions`, `booking_resolutions`, `booking_imports`, `calendar_feeds`, `trip_fact_observations`, `trip_fact_checks`, `preference_dismissals`; `lib/db/execution-repository.ts`). Opening a trip, a calendar, an image, Preflight, Today or the Pack runs no model and no provider; a recheck is a throttled server action a client effect calls, it writes observations and never edits the plan (`detect → explain → propose → the traveller accepts → reverify`). A booked fact carries `bookingItemId` and outranks the need it satisfies; "Mark booked / Add confirmation / Replace / Skip" act on needs, a confirmation import stores only the redacted extraction until the traveller confirms, and `applyBookedFacts` reports its affected radius. Ask Sidequest shows a deterministic delta (`execution/delta.ts`) before Apply and the measured metrics delta after; Apply records a decision, Undo is the exact state restore. Calendar output (snapshot and revocable hashed-token feed) comes from one pure builder with `TZID`/`VTIMEZONE`, stable UIDs and `SEQUENCE`; feeds, images and shares carry no references, notes, costs or party facts. Never invent urgency, prices, hours or availability; unknown ≠ false throughout.

- **Execution reliability (V9.1, `.claude-private/V9.1-EXECUTION-RELIABILITY.md`).** A structural refinement answers with a **patch, never a rewritten itinerary**: one bounded `restructure` operation (stays and their nights, what to drop, what to move) that `expandRestructure` turns deterministically into the existing typed operations, so nothing reaches the itinerary through a path the invariants do not already police. The model never restates a day that does not change, `changed`/`kept` prose is optional, a structural request is recognised deterministically (`isStructuralRequest`) and runs on the compact index — the V9 refinement died on its deadline through output volume, not input size (`V9.1-REFINEMENT-PROFILE.md`). Still one call, no critic, no retry. Anything that leaves the owner's hands is stripped **including the second copies**: the intelligence snapshot carries its own booked list and its own spend, and the stripped snapshot — never the original — is what the graph, the next actions and Preflight are rebuilt from. iCalendar folds on **octets**, never characters. A fixture token (`unbuildable`, `slowbuild`, `multibase`) is read from what the traveller typed (`FixtureComposerHints.destinationInput`), never from the resolved envelope name. A performance measurement runs in its own pass (`npm run test:perf`), never inside `npm run test`, where it starves the suite and makes the gate lie. **A read-only share is a boundary, not a filter**: `loadTripIntelligence({ audience: 'public' })` builds it with no readiness profile, no party diet or accessibility facts and booked facts reduced to what shapes the plan, and never touches the owner's stored snapshot — entry and visa sentences are composed at build time and copied into five derived layers, so the only way a nationality does not appear in prose is for it never to have been an input. **A routing silence is never a verdict (V9.1, `.claude-private/V9.1-ROUTING-CONTRADICTION.md`).** `AUTHORITATIVE_NO_ROUTE` may only come from a provider that evaluated two resolved endpoints on the requested profile and explicitly reported no route — the direct route endpoint answering NO_PATH. A declined matrix cell is `insufficient_evidence`: Valhalla's `costmatrix` returns a null `time` for pairs `/route` solves, and reading that as positive evidence removed a 56-minute drive from a real trip as unreachable. Timeouts, 5xx, malformed or empty bodies, rate limits, out-of-coverage, unreachable routers and missing cells are all absences, never contradictions; a `core` stop leaves a plan only on affirmative evidence, never because a measurement failed to arrive. **Nothing in a model wire is enforced by the provider**: `zodOutputFormat` folds every `enum`, `const` and `maxLength` into a `description` string, and the refinement's schema does not compile at all (`enforcement: ['grammar','prompt']`), so every closed vocabulary must be stated in the prompt and every constraint is checked only afterwards by zod — where a hard field (an enum, an identifier, a night count) throws and only free prose may be deterministically clipped through `structured()`'s `normalize` hook.

- **World-class itinerary intelligence (V10, `.claude-private/V10-ITINERARY-INTELLIGENCE.md`).** One canonical `DestinationConcept` (`packages/core/src/destinations/semantics.ts`, the V8.1 semantics record renamed) travels from setup through the questionnaire, composition and the itinerary; the interpreter's own contract is `InterpretedConcept`. **A destination region may never become its containing country** — `centerBasis` distinguishes a country the phrase *named* (`country_qualified`, honest) from one inferred from a demonym (`country_reference`, a stand-in), `degradedToCountry` refuses the collapse, and `framingIsUnsafe` makes the canvas say "Locating this mountain region…" rather than draw a country. Jurisdiction is separate from destination: `jurisdictions` carries country and ISO 3166-2 subnational rows, and every sentence about money, visas, driving or passes reads `jurisdictionPhrase`, never the destination label. A broad region is decomposed before composition into a coverage graph (`destinations/decomposition.ts`: core/optional/gateway zones, derived roles, relations) and the composition call receives it, the gateways, the access facts and explicit route objectives (`route/objectives.ts`), and must state one `routeAlternative` and explain every core zone it omits. Four anchor classes are **route-critical** (`route/critical.ts`): a base, gateway or route-defining stop is asked for through the `placementQueries` ladder — locality, province, country, hedge words stripped, most-qualified first — every query is recorded on `package.placement`, and `placementBlocksReady` gates "Ready" only where a provider answered unusably, never on Sidequest's own gaps (§19). `route/spatial-order.ts` detects reversals, arrival-before-en-route and duplicate crossings, `correctDayOrder` corrects before the legs are built (never after), a pinned stop holds its index, and a day with an unplaced stop is `unplaceable` rather than silently clean. **`morning`/`afternoon` are soft** (`timeOfDayIsHard`): only `sunrise`, `sunset` and `night` outrank geography, because the V5 §13 hour sort moved a "morning" stop 30 km past the one on the way to it and bought a 49 km detour. Experiences are hierarchical (`experience/graph.ts`: access legs and components); movement *inside* an experience is never transportation between stops (`transportBetweenStops`) and one connected experience is never counted twice (`doubleCounted`); the derivation (`planning/experience-graph.ts`) is conservative — only an official required mode and containment the draft states itself create structure. Gateways are first-class (`gateway/plan.ts`): arrival, first base, final base and departure are four things, the allowances are named, and an unstated flight holds a conservative window. `access/constraints.ts` holds effective-dated, sourced, statused, moded operational claims loaded as data per ISO country code (`providers/fixtures/access/`); only `official_current` and `operator` may establish a status, `unknown` is never `open`, and a required mode is a dependency in words ("Moraine Lake requires a shuttle — reserve this"), never a field name. BEST_TIME is multi-objective (`activityAccess`, `severeWeather`, `phenomena`, `scenic` added) and access is stated as a historical likelihood, never a certainty. `planning/quality-compiler.ts` runs fifteen checks on every build, corrects only what is safely derivable, and records every check it could not run with its reason — an unrun check is never a pass. Routing measures a day in one ORS matrix request with a seven-day cache; a declined cell is `insufficient_evidence`, never a verdict. Never patch a destination, a place or a closure by name.

- **Product intelligence (V11, `.claude-private/V11-PRODUCT-INTELLIGENCE.md`).** A bad number dies before the UI: one mode-aware envelope (`packages/core/src/travel/plausibility.ts`) screens **both** routers — openrouteservice had no gate at all, which is how 434 km in 5,209 minutes shipped as a *measured* private transfer, and Valhalla's own 5 km/h car floor would have admitted it. A refused measurement is `insufficient_evidence`, never `not_found`; the endpoints survive so only the clock loses its figure. Speed floors are banded by leg length, because one floor either admits a 434 km crawl or refuses ordinary congestion. **The derived stay sequence is the authority, not the base list** (`experience/chapters.ts`): consecutive same-place stays collapse, a night a multi-day experience owns is never a hotel change, and chapters come from geography + experiences + route structure with `recovery` assigned only where no day is strenuous *and* no day is mostly travel. **"What the trip is built around" is scored, never sliced** (`experience/signature.ts`): seven weighted signals led by the draft's own stated signatures and by whether the anchor belongs to a multi-day experience — `.slice(0, 3)` over day order is what made a bazaar the point of a trek and an arrival-evening stroll the point of the Rockies. Effort is traveller-relative and a market is never penalised for being a market. **Ready is gated per archetype** on the route-critical set (`feasibility/readiness-requirements.ts`), never on a leg percentage, and never asks an operator-led trek for road-measured trail legs. **Sidequest's own unfinished work is never a traveller action**: `FeasibilityItem.owner` reaches the state graph, `buildNextActions` drops it, and `feasibilityHeadline` says "Not ready yet — nothing for you to do yet" instead of "Needs a decision". A mode correction may only produce a mode the trip actually uses (`plausibleModeFor`'s `arrangement`), read from `draft.driving` and then from the days' own hints. Every sentence about money, plugs, languages, licences and emergency numbers names the **jurisdiction** (`readiness.ts` reads the bundled country row), never the destination. An operator-run multi-day episode is a budget bundle, a multi-day trek is its own weather signal for packing, and a day the operator caters is never told to buy lunch the evening before. `quality/trip-quality.ts` scores twelve dimensions separately and **never one score**; `execution/assurance.ts` folds eighteen status labels into four traveller words. Founder fixtures: `planning/acceptance/founder-v11.test.ts`, failure matrix all zeros. Never patch a trip, a place or a measurement by name. **A duration is a fact; a position is a placement, and the two are separate** (V11 §1): itinerary items carry `timelineMinuteSchema` (0–48 h), not `minuteOfDaySchema`, because a day that overruns puts real stops past midnight — deriving `durationMinutes` from two ends clamped at 24:00 is what shipped "0 min Walk to Karakol · base to base measured". `span(start, duration)` in `reconcile.ts` is the only way an item's three time fields are built, and `formatTimelineMinute`/`timelineClock` wrap the clock and say that it wrapped. Never reintroduce a `clamp`-derived duration and never widen `minuteOfDaySchema`, which is a clock reading that opening hours, sunset and departure times all depend on. The destination recommender this paragraph once described (`recommend/rank.ts`, `recommend/proposal.ts`) was replaced by the advisor and then by global destination intelligence (below); its one surviving rule is that the advisor's answers live on `TripComposerAnswers`, so "Plan this" carries them with no mapping layer. **Traveller-facing status is four words** (`execution/assurance.ts`), which `HumanWords.ts` derives from rather than restates; `/labs/design` is the visual source of truth and inherits the `/labs` gate. Map framing is decided once in `map-camera.ts` with a stated basis, a missing point is absent rather than fatal, and one placed point borrows context instead of zooming into a creek.

- **Production pass (2026-10, `docs/production-pass/`).** A discovery scan never dies on the model alone: when the proposal call is unavailable (not configured, key rejected, allowance spent, timeout, 5xx), `discovery-scan/open-data-proposal.ts` builds the candidate pool from Wikidata first (one Query Service `around` request, `providers/wikidata-around.ts`, types mapped to OSM-style tags through one curated table) merged with OpenStreetMap (Overpass, `wikidata`-tagged only, asked only while Wikidata is thin; a failing endpoint cools down for ten minutes process-wide), deterministically, with no model call, and the board says so (`diagnostics.proposalSource = 'open_data'`); a malformed model answer still fails honestly, and an open-data failure reports the model's original cause. Needs `SIDEQUEST_POI_PROVIDER=overpass`. Every scan records `diagnostics.timings`. Visual identity is the Field Atlas system (`docs/production-pass/design-system.md`): Fraunces/Bricolage Grotesque/JetBrains Mono, night/bone/flare/glacier, the generated contour sheet as the only texture, flare for the one action that moves a trip forward; the landing globe and scan map draw only real coordinates (examples are labelled "Example shape"), with attribution visible. **Release pass (2026-11):** the scan's food reads Overture's place files first (keyless, `providers/overture-food.ts`; public Overpass only fills thin boxes, 8 s a request); the travel estimator's speed is interpolated between anchors so time is continuous and never shorter for a longer leg, and recorded live scans (`packages/core/src/scan/live-scans.test.ts`) guard base choice; a near-empty first proposal makes the one supplement ask for the full pool, then open data tops up with no model call, and a board still short says so.

- **Global destination intelligence (2026-11, `docs/global-destinations/`, supersedes the 234-entry catalog as the candidate universe).** "Help me choose" ranks **one world**: the atlas (`packages/atlas/data/atlas.json.gz`, ~36,800 destinations, built offline by `packages/atlas/build/` from Wikivoyage, Wikidata, CHELSA climate normals, ETOPO, NOAA OISST, OurAirports and World Bank price levels) with the 234 curated entries (`packages/core/src/advisor/catalog/regions/`) standing in for their derived twins. Nothing is downloaded at request time or at start-up; a rebuild is a new commit, and a missing artifact degrades to the curated catalog and says so (`lib/atlas/world.ts`). **Measured ≠ estimated ≠ editorial**: every `Destination` (`advisor/destination.ts`) carries `origin`, `basis` per field group, `confidence` and `substance`; what a derived place *offers* is an estimate fitted to the curated labels in `06-assemble.mjs` (held-out agreement in `data/manifest.json`), and the scorer discounts a thin reading (`trust`) rather than believing or discarding it — unknown ≠ false. **Two stages**: `Atlas.candidates` makes one pass over every row (scope, offer, activity season, lexical + meaning match, resemblance) and hands a few hundred to the unchanged twelve-factor scorer (`advisor/score.ts`); the same ground is never offered twice (`select.ts#overlap`: hierarchy, shared QID, extents). **Seasonality is per activity** (`atlas/seasonality.ts`): fifteen activities by month from normals where people stay *and* at trekking altitude, a modelled snowpack, sea-surface temperature and day length — ski season is not hiking season, and an editorial season curve can veto a month but never make a snowbound trail walkable. **A named place is a scope, a comparison, a refusal or an origin, never the answer** (`Atlas.findPlaces`, read by `advisor/parse.ts`): "in the Karakoram", "like the Dolomites", "not Bali", "from Delhi"; the language tables that reading needs are data in `naming/place-words.ts`. The request's own words reach retrieval through a BM25 index and an optional static-embedding channel (`atlas/embed.ts`, potion-base-8M, no inference runtime) — lexical dominant, the meaning channel additive, and a guide's words may lift a place but never sink one. **A model may propose a place; it may not recommend one** (`lib/atlas/research.ts`): at most one bounded, cached call per shortlist, only when `needsResearch` says the list is weak, after the deterministic list is already on screen; every name is resolved against the atlas or dropped, joins the candidates under the same constraints and scorer, and its card says so. A fresh do-not-travel advisory removes a place; a stale one is only a caution (`ADVISORY_FRESH_DAYS`). The interview's questions are client data (`advisor/questions.ts`); choosing the next one ranks the world and runs on the server (`advisor/interview-policy.ts`, `advisorStepAction`). The previous engines (`recommend/`, `lib/destinations/recommend.ts`, `DecisionComposer`/`ShortlistView`) are deleted; old stored sessions re-enter the interview with their answers. A chosen destination is still an ordinary trip whose `destinationQuery` is `resolveAs`. Evaluation: the curated-only regression eval (`advisor/eval/`, 42 scenarios), the shipped-artifact tests (`packages/atlas/src/atlas.test.ts`) and the global benchmark against the frozen 234 baseline (`packages/atlas/src/benchmark.harness.ts`, 147 requests). Never patch a destination, a season or a result by name; never present an estimate as a measurement.

- **Release-candidate pass (2026-11, `docs/release-candidate/`).** Where to sleep is **one objective** (`packages/core/src/scan/stay-objective.ts`): day travel + transfers + move overhead + the traveller's stated tolerance for moving + what goes unseen, in minutes, with named parts and must-dos compared first; there is no "one base per island" rule, and the decision with its numbers is on `itinerary.package.planning.stay`. Days a traveller's limit cannot hold are repaired (`planning/structure-repair.ts`) or stated on the day, never hidden. Food is ranked by stated terms in kilometres (`packages/core/src/food/meal-rank.ts`), chains are labelled and never excluded, a sparse area names a real shop or says to bring food, and hours are never implied. The atlas gained real geometry, three governments' advice and destination evidence, all built offline: a do-not-travel removes a place only when the warned area contains it (`build/lib/evidence.mjs`); a warning that cannot be placed stays a caution and nothing is ever called safe because no warning matched; advisory freshness is judged on the fetch date, because an unedited level 4 is still in force. Experience estimators have a fifth, activity-specific signal (`build/lib/specialist.mjs`). **`packages/atlas/data/ski-areas.odbl.json.gz` is a separate ODbL database joined in memory (`Atlas.attachSkiAreas`); never write values derived from it into `atlas.json.gz`.** A vague request is a set of `moods` (a leaning, scored on the best a place has, stated back as an assumption) and a precise wish is a `pursuit`; a whole country stands down for one of its own regions (`advise.ts#withoutBroadStandIns`). Two places on different landmasses are different trips. Map and itinerary share one selection (`components/hub/TripSelection.tsx`); every hand edit is a version and can be undone.

- **Travel quality and planning correctness (2026-11, `docs/experience-transformation/eval-v2/`).** Every planner build is held to a **trip-quality contract** (`packages/core/src/quality/trip-quality-contract.ts`, glue `planning/quality-contract.ts`): purpose, essential experiences (from the traveller's words, the destination's semantic type and the discovery call's own `defining` marks — at most three), requirements vs preferences, transport, structure and timing, built before the days and checked after; a missing essential is attributed to discovery, selection or scheduling, persisted on `itinerary.package.qualityContract` and stated on the overview with a recovery path. The planner builds around essential candidates (`ESSENTIAL_BONUS`, below the traveller's own picks). Activity word tables are data; never a place. **Transport is one decision** (`packages/core/src/travel/arrangement.ts#decideTripArrangement`): operator, private driver, transfers, self-drive, public transport, mixed — bookings, budget, Prepare, booking links, leg wording and day titles all read it; an operator trip is never a rental car, and the operator's vehicle applies only on the days it runs. **Sky-timed stops** use the day's real sunrise/sunset/twilight in the destination's zone (`planning/sky-timing.ts`); stargazing is never in daylight and is left unscheduled, with a reason, where the night never gets dark. A slow trip gets no dawn start it did not pick. **Trails:** a point-to-point stage that ends at the next bed makes the move the walk (`scan/stay-objective.ts#TrailLink`); a single bed pays the way back from a one-way stage. A day trip beyond the usual reach must be worth its travel (`DAY_TRIP_VISIT_SHARE`). The advisor never ranks first a place its own card calls unsuitable for the primary intent (`advisor/conflicts.ts`). A stated "by train"/"by car" in the destination is the transport answer (`destinations/stated-mode.ts`) and never part of a place name; high-speed rail is an estimator profile where the country's facts make it the backbone.
